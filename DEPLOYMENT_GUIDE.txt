  6. Verify: curl http://your-domain.com/

  1. SSH to web server
  2. Create directory: /var/www/crm-frontend/
  3. Upload dist files

     <IfModule mod_rewrite.c>
       RewriteEngine On
       RewriteBase /
       RewriteRule ^index\.html$ - [L]
       RewriteCond %{REQUEST_FILENAME} !-f
       RewriteCond %{REQUEST_FILENAME} !-d
       RewriteRule . /index.html [L]
     </IfModule>
  5. Restart Apache: sudo systemctl restart apache2
  6. Verify: curl http://your-domain.com/

                      STEP 6: ROLLBACK PROCEDURE
================================================================================

IF SOMETHING GOES WRONG:

Immediate Rollback:
  1. Keep previous JAR file backed up
  2. If backend fails: Replace JAR, restart
  3. If frontend fails: Rollback to previous dist, redeploy
  4. Expected recovery time: 5-10 minutes

Database Rollback:
  NOT NEEDED - No schema changes made
  All new columns already exist in database
  Data is safe, just new values being populated

Data Safety:
  All tracking data goes to new fields
  No existing data is modified
  No data loss possible

Revert Changes:
  1. Stop new application
  2. Restore previous JAR
  3. Restart application
  4. Restore previous dist folder
  5. System returns to previous state
