REACT QUERY BEHAVIOR ANALYSIS
═══════════════════════════════════════════════════════════════════════════════

QUESTION: When enabled changes from false → true, does React Query re-execute queryFn?

React Query Documentation:
  - enabled: boolean - set to true to enable the query
  - When enabled changes from false to true, React Query DOES re-fetch
  - The queryFn should be called automatically

However, CRITICAL observation from code:

DASHBOARD.JSX LINE 104:
  ```
  const { data: dashboardData, isLoading, error } = useQuery({
    queryKey: ['dashboard', currentWorkspace?.id],  // ← DEPENDENCY IS INCLUDED
    queryFn: () => { ... },
    enabled: !!currentWorkspace?.id,  // ← MATCHES queryKey dependency
  })
  ```

REACT QUERY BEHAVIOR:
  When queryKey changes, React Query treats it as a NEW query.
  - queryKey: ['dashboard', null] (first render)
  - queryKey: ['dashboard', 1] (after Redux updates)
  - These are DIFFERENT cache keys
  - So React Query WILL execute queryFn for ['dashboard', 1]

But CONSTRAINT: enabled condition must ALSO be true
  - enabled: !!null = false (first render)
  - Query NOT executed even though queryFn exists
  
  THEN:
  - enabled: !!1 = true (after Redux updates)
  - NEW queryKey: ['dashboard', 1]
  - React Query SHOULD execute queryFn now
