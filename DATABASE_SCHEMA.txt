TABLE 1: email_campaigns
================================================================================

Purpose: Stores email campaign metadata

Existing Fields (ALL USED BY NEW FEATURE):
  id BIGSERIAL PRIMARY KEY
    - Unique campaign identifier
    - Auto-generated
  
  workspace_id BIGINT NOT NULL (FK workspaces.id)
    - References workspace owner
  
  name VARCHAR(255) NOT NULL
    - Campaign name (e.g., "Summer Sale 2024")
  
  subject VARCHAR(255) NOT NULL
    - Email subject line
  
  description TEXT
    - Campaign description
  
  template_id BIGINT (FK email_templates.id)
    - Optional reference to template
  
  content_type VARCHAR(50)
    - Values: TEMPLATE, CUSTOM_HTML, MARKDOWN
  
  status VARCHAR(50) NOT NULL
    - Values: DRAFT, SCHEDULED, SENDING, SENT, COMPLETED, PAUSED, FAILED, ARCHIVED
  
  is_active BOOLEAN
    - Whether campaign is active
  
  created_by_id BIGINT (FK users.id)
    - User who created campaign
  
  scheduled_at TIMESTAMP
    - When campaign should send
  
  send_started_at TIMESTAMP
    - When sending started
  
  send_completed_at TIMESTAMP
    - When sending completed
  
  total_recipients BIGINT
    - Total recipients (used by analytics)
  
  sent_count BIGINT
    - Count of emails sent
  
  failed_count BIGINT
    - Count of failed sends
  
  delivered_count BIGINT DEFAULT 0
    - Count of emails delivered (UPDATED BY TRACKING)
  
  opened_count BIGINT DEFAULT 0
    - Count of emails opened (UPDATED BY TRACKING)
  
  clicked_count BIGINT DEFAULT 0
    - Count of emails clicked (UPDATED BY TRACKING)
  
  bounced_count BIGINT DEFAULT 0
    - Count of bounced emails
  
  segment_filter JSONB
    - JSON filter for segments
  
  recipient_mode VARCHAR(50)
    - Values: MANUAL, SEGMENT, CRM_FILTER
  
  recipient_data JSONB
    - JSON recipient data
  
  created_at TIMESTAMP NOT NULL
  
  updated_at TIMESTAMP
  
  deleted_at TIMESTAMP

Indexes:
  - PRIMARY KEY: id
  - FOREIGN KEY: workspace_id, template_id, created_by_id
  - Indexes: workspace_id, status, created_at, workspace_id+status, scheduled_at

New Feature Usage:
  - delivered_count: Incremented when email delivered
  - opened_count: Incremented when email opened
  - clicked_count: Incremented when email clicked
  - All fields already exist, no migration needed

TABLE 2: email_campaign_recipients
================================================================================

Purpose: Stores individual recipient data and tracking information

Existing Fields (ALL USED BY NEW FEATURE):
  id BIGSERIAL PRIMARY KEY
    - Unique recipient identifier
  
  campaign_id BIGINT NOT NULL (FK email_campaigns.id)
    - Campaign this recipient belongs to
  
  lead_id BIGINT (FK leads.id)
    - Optional reference to lead
  
  recipient_email VARCHAR(255) NOT NULL
    - Recipient email address
  
  recipient_name VARCHAR(255)
    - Recipient name
  
  recipient_company VARCHAR(255)
    - Recipient company
  
  recipient_variables JSONB
    - Custom template variables
  
  status VARCHAR(50) NOT NULL
    - Values: PENDING, QUEUED, SENT, DELIVERED, OPENED, CLICKED, BOUNCED, FAILED, UNSUBSCRIBED
    - UPDATED BY TRACKING
  
  bounce_type VARCHAR(50)
    - Values: PERMANENT, TEMPORARY
  
  delivery_attempts INT
    - Number of delivery attempts
  
  sent_at TIMESTAMP
    - When email was sent (USED BY TRACKING)
  
  delivered_at TIMESTAMP
    - When email was delivered (USED BY TRACKING)
  
  opened_at TIMESTAMP
    - When email was opened (UPDATED BY TRACKING PIXEL)
  
  first_clicked_at TIMESTAMP
    - When user first clicked CTA (UPDATED BY TRACKING)
  
  last_clicked_at TIMESTAMP
    - When user last clicked CTA (UPDATED BY TRACKING)
  
  click_count INT DEFAULT 0
    - Number of clicks (UPDATED BY TRACKING)
  
  unsubscribed_at TIMESTAMP
    - When user unsubscribed
  
  provider_message_id VARCHAR(255)
    - Brevo message ID for this recipient
  
  error_message TEXT
    - Error details if failed
  
  metadata JSONB
    - Additional metadata
  
  created_at TIMESTAMP NOT NULL
  
  updated_at TIMESTAMP

Constraints:
  - UNIQUE (campaign_id, recipient_email)
  - PRIMARY KEY: id
  - FOREIGN KEY: campaign_id, lead_id

Indexes:
  - PRIMARY KEY: id
  - FOREIGN KEY: campaign_id, lead_id
  - Composite: campaign_id+status, campaign_id+recipient_email
  - Single: status, email, opened_at

New Feature Usage:
  - opened_at: Set when tracking pixel loads (first open only)
  - first_clicked_at: Set when CTA clicked (first click only)
  - last_clicked_at: Updated on every click
  - click_count: Incremented on every click
  - status: Transitions through: PENDING > SENT > DELIVERED > OPENED > CLICKED
  - All fields already exist, no migration needed

TABLE 3: email_campaign_history
================================================================================

Purpose: Append-only audit log of all events

Existing Fields (ALL USED BY NEW FEATURE):
  id BIGSERIAL PRIMARY KEY
    - Unique history record identifier
  
  campaign_id BIGINT NOT NULL (FK email_campaigns.id)
    - Campaign this event belongs to
  
  recipient_id BIGINT (FK email_campaign_recipients.id)
    - Recipient this event relates to
  
  recipient_email VARCHAR(255)
    - Email address for reference
  
  event_type VARCHAR(50) NOT NULL
    - Values: SENT, DELIVERED, OPENED, CLICKED, HARD_BOUNCE, SOFT_BOUNCE, SPAM, UNSUBSCRIBE, REPLY
    - POPULATED BY TRACKING
  
  link_url TEXT
    - URL that was clicked (if applicable)
  
  bounce_reason VARCHAR(255)
    - Reason for bounce (if bounce event)
  
  provider_event_id VARCHAR(255)
    - Brevo event ID for deduplication
  
  metadata JSONB
    - Event metadata (user agent, IP, etc.)
  
  occurred_at TIMESTAMP NOT NULL
    - When event occurred (USED BY TRACKING)
  
  created_at TIMESTAMP NOT NULL

Constraints:
  - PRIMARY KEY: id
  - FOREIGN KEY: campaign_id, recipient_id
  - UNIQUE: provider_event_id

Indexes:
  - PRIMARY KEY: id
  - FOREIGN KEY: campaign_id, recipient_id
  - Single: event_type, recipient_email, occurred_at
  - Composite: campaign_id+event_type, campaign_id+recipient_email, provider_event_id

New Feature Usage:
  - event_type: OPENED and CLICKED (created by server-side tracking)
  - occurred_at: Set to current timestamp
  - metadata: Contains source: "server_side_tracking"
  - Provides complete audit trail of all tracking events
  - All fields already exist, no migration needed

================================================================================
                     FIELD VALUE RANGES
================================================================================

Tracking Fields - Before Tracking:
  opened_at: NULL
  first_clicked_at: NULL
  last_clicked_at: NULL
  click_count: 0
  status: SENT

Tracking Fields - After Email Opened:
  opened_at: <timestamp>
  first_clicked_at: NULL (unless also clicked)
  last_clicked_at: NULL (unless clicked)
  click_count: 0 (unless clicked)
  status: OPENED

Tracking Fields - After CTA Clicked:
  opened_at: <timestamp or NULL> (unchanged if already set)
  first_clicked_at: <timestamp> (set only if NULL)
  last_clicked_at: <timestamp> (always updated)
  click_count: >= 1 (incremented)
  status: CLICKED

Tracking Fields - After Multiple Clicks:
  opened_at: <original timestamp>
  first_clicked_at: <original timestamp> (never changes)
  last_clicked_at: <most recent timestamp>
  click_count: >= 2 (incremented each time)
  status: CLICKED

Status Transitions:
  PENDING → SENT (email sent to Brevo)
  SENT → DELIVERED (Brevo webhook or delivery confirmed)
  DELIVERED → OPENED (tracking pixel loaded OR Brevo webhook)
  OPENED → CLICKED (CTA clicked)
  Any → BOUNCED (bounce event from Brevo)
  Any → FAILED (send failed)
  Any → UNSUBSCRIBED (unsubscribe from Brevo)

================================================================================
                    DATABASE QUERIES
================================================================================

CHECK IF TRACKING WORKING:

1. Count delivery events:
  SELECT 
    campaign_id,
    COUNT(*) as total,
    COUNT(delivered_at) as delivered,
    COUNT(CASE WHEN delivered_at IS NOT NULL THEN 1 END) as delivered_check
  FROM email_campaign_recipients
  GROUP BY campaign_id
  ORDER BY campaign_id DESC
  LIMIT 5;

2. Check open tracking:
  SELECT 
    recipient_email,
    campaign_id,
    opened_at,
    status
  FROM email_campaign_recipients
  WHERE opened_at IS NOT NULL
  ORDER BY opened_at DESC
  LIMIT 10;

3. Check click tracking:
  SELECT 
    recipient_email,
    campaign_id,
    first_clicked_at,
    last_clicked_at,
    click_count,
    status
  FROM email_campaign_recipients
  WHERE first_clicked_at IS NOT NULL
  ORDER BY first_clicked_at DESC
  LIMIT 10;

4. Check history events:
  SELECT 
    event_type,
    COUNT(*) as count,
    MAX(occurred_at) as latest
  FROM email_campaign_history
  WHERE created_at > NOW() - INTERVAL '1 hour'
  GROUP BY event_type
  ORDER BY count DESC;

5. Verify metrics accuracy:
  SELECT 
    c.id as campaign_id,
    c.name as campaign_name,
    c.total_recipients,
    c.sent_count,
    c.delivered_count,
    c.opened_count,
    c.clicked_count,
    COUNT(cr.id) as recipient_count,
    COUNT(CASE WHEN cr.delivered_at IS NOT NULL THEN 1 END) as counted_delivered,
    COUNT(CASE WHEN cr.opened_at IS NOT NULL THEN 1 END) as counted_opened,
    COUNT(CASE WHEN cr.first_clicked_at IS NOT NULL THEN 1 END) as counted_clicked
  FROM email_campaigns c
  LEFT JOIN email_campaign_recipients cr ON c.id = cr.campaign_id
  WHERE c.status = 'SENT'
  GROUP BY c.id, c.name, c.total_recipients, c.sent_count, c.delivered_count, c.opened_count, c.clicked_count
  ORDER BY c.id DESC
  LIMIT 5;

6. Check for tracking errors:
  SELECT 
    cr.recipient_email,
    cr.campaign_id,
    cr.status,
    cr.error_message,
    COUNT(h.id) as history_events
  FROM email_campaign_recipients cr
  LEFT JOIN email_campaign_history h ON cr.id = h.recipient_id
  WHERE cr.status = 'FAILED'
  GROUP BY cr.id, cr.recipient_email, cr.campaign_id, cr.status, cr.error_message
  ORDER BY cr.updated_at DESC
  LIMIT 10;

================================================================================
                    DATA CONSISTENCY
================================================================================

Ensuring Data Integrity:

1. Timestamps are consistent:
  - delivered_at: Set only by Brevo webhook (authoritative)
  - opened_at: Set by tracking pixel (first time only)
  - first_clicked_at: Set by tracking endpoint (first time only)
  - last_clicked_at: Always updated by tracking endpoint

2. Status transitions are unidirectional:
  - PENDING → (other states)
  - SENT → (same or later states)
  - Final states: DELIVERED, BOUNCED, FAILED, UNSUBSCRIBED

3. Count-only-once logic:
  - opened_at is set only if NULL (prevents double-count)
  - first_clicked_at is set only if NULL (prevents double-count)
  - click_count is incremented (allows multiple counts)
  - Provides accurate one-time metrics

4. History audit trail:
  - All changes recorded in history table
  - provider_event_id prevents duplicate Brevo events
  - occurred_at timestamp for event ordering

5. Referential integrity:
  - All foreign keys defined
  - Cascade delete on campaign delete
  - Prevents orphaned records
