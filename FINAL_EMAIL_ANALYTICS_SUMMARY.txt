ARCHITECTURE OVERVIEW
═════════════════════════════════════════════════════════════════════════════════

Email Campaign Workflow:
  1. User creates campaign (DRAFT)
  2. User adds recipients (status: PENDING)
  3. User sends campaign
  4. Backend marks recipients as SENT
  5. ✅ Brevo processes email delivery
  6. ✅ Brevo sends webhook: SENT → (POST /api/webhooks/brevo)
  7. ✅ Backend updates: status = SENT, sentAt = timestamp
  8. ✅ Campaign metrics updated: sentCount++
  9. ✅ Recipient opens email
  10. ✅ Brevo sends webhook: OPENED
  11. ✅ Backend updates: status = OPENED, openedAt = timestamp
  12. ✅ Campaign metrics updated: openedCount++
  13. ✅ Frontend displays updated metrics in real-time

Analytics Data Flow:
  Frontend (EmailCampaignDetails.jsx)
    ↓
    useQuery: GET /api/workspaces/{id}/email-campaigns/{id}/analytics
    ↓
    Backend (EmailCampaignController)
    ↓
    Service (EmailCampaignServiceImpl)
    ↓
    Repository Query: COUNT recipients by status
    ↓
    Response: {sentCount, deliveredCount, openedCount, clickedCount, bouncedCount}
    ↓
    Frontend displays metrics and calculates rates
