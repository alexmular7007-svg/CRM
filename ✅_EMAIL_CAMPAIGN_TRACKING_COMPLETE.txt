================================================================================
                        EMAIL FLOW (UPDATED)
================================================================================

1. USER CREATES CAMPAIGN
   - Form captures: name, subject, content, CTA button URL/text, template
   - CTA fields: ctaButtonUrl, ctaButtonText (already existed)
   - Submit to backend: POST /api/campaigns

2. BACKEND SENDS EMAIL
   - Loads campaign and recipients
   - FOR EACH RECIPIENT:
     a) Render email HTML template
     b) Add CTA button with TRACKING URL:
        href="/api/campaigns/track/click?campaignId=X&recipientId=Y&redirect={encoded_url}"
     c) Inject open tracking PIXEL:
        <img src="/api/campaigns/track/open?campaignId=X&recipientId=Y" ... />
     d) Send to Brevo API with metadata

3. EMAIL SENT TO RECIPIENT
   - Recipient receives beautiful email with CTA button
   - CTA button links to tracking endpoint (not direct)
   - Open pixel embedded in email body

4A. RECIPIENT OPENS EMAIL
   - Email client loads pixel
   - Pixel request → GET /api/campaigns/track/open
   - Backend records OPEN event
   - Pixel returns 1x1 GIF (invisible to user)
   - Database updated: openedAt timestamp
   - Analytics updated: openedCount++

4B. RECIPIENT CLICKS CTA BUTTON
   - User clicks CTA link
   - Browser sends request → GET /api/campaigns/track/click
   - Backend records CLICK event
   - Backend redirects: HTTP 302 → original URL
   - User sees destination (transparent to them)
   - Database updated: firstClickedAt, lastClickedAt, clickCount
   - Analytics updated: clickedCount++

5. BREVO WEBHOOK (EXISTING)
   - Brevo also sends webhook for bounce/complaint/etc.
   - Dual tracking: Server-side + Brevo webhook
   - Redundant data collection for accuracy

6. ANALYTICS DASHBOARD
   - Shows all metrics: Recipients, Delivered, Opened, Clicked
   - Shows rates: Delivery %, Open %, Click %
   - Shows recipient activity table
   - Shows campaign timeline
   - Shows events breakdown
