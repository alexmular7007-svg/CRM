WEBHOOK EVENT FLOW
═══════════════════════════════════════════════════════════════════════════════

When Recipient Opens Email:
  1. Brevo detects email open
  2. Brevo sends POST /api/webhooks/brevo with:
     {
       "event": "OPENED",
       "email": "user@example.com",
       "message_id": "brevo_123456",
       "ts": 1691000000,
       "metadata": {"campaign_id": 1, "recipient_id": 1},
       "user_agent": "Mozilla...",
       "ip": "192.168.1.1"
     }
  3. BrevoWebhookController receives request
  4. EmailAnalyticsService.processWebhookEvent() called
  5. Validates payload and checks for duplicates
  6. Finds recipient by campaign_id + email
  7. Updates recipient:
     - status = "OPENED"
     - opened_at = current timestamp
     - updated_at = now
  8. Creates history record:
     - event_type = "OPENED"
     - occurred_at = webhook timestamp
     - metadata = {user_agent, ip}
  9. Updates campaign metrics:
     - opened_count = (count of recipients with status='OPENED')
  10. HTTP 200 OK returned to Brevo
  11. Response persisted (optimistic updates)

Similar flow for: DELIVERED, CLICKED, HARD_BOUNCE, SOFT_BOUNCE, SPAM, UNSUBSCRIBE

═══════════════════════════════════════════════════════════════════════════════
RECIPIENT STATUS LIFECYCLE
═══════════════════════════════════════════════════════════════════════════════

Success Path:
  PENDING → SENT → DELIVERED → OPENED → CLICKED

Bounce Path:
  PENDING → SENT → BOUNCED (hard or soft)

Unsubscribe Path:
  PENDING → SENT → DELIVERED → OPENED → UNSUBSCRIBED

Spam Path:
  PENDING → SENT → DELIVERED → SPAM

Field Updates:
  - sentAt: When SENT event received
  - deliveredAt: When DELIVERED event received (cleared if bounce)
  - openedAt: First OPENED event (never updated again)
  - firstClickedAt: First CLICKED event (never updated again)
  - lastClickedAt: Most recent CLICKED event (updated for each click)
  - clickCount: Incremented for each CLICKED event
  - unsubscribedAt: When UNSUBSCRIBE event received
  - bounceType: PERMANENT (hard_bounce) or TEMPORARY (soft_bounce)

═══════════════════════════════════════════════════════════════════════════════
CAMPAIGN METRICS UPDATES
═══════════════════════════════════════════════════════════════════════════════

Updated on every webhook event:
  - deliveredCount: COUNT(recipients where status='DELIVERED')
  - openedCount: COUNT(recipients where status='OPENED')
  - clickedCount: COUNT(recipients where status='CLICKED')
  - bouncedCount: COUNT(recipients where status='BOUNCED')

Calculated from recipient counts (not webhook counts) to ensure accuracy:
  - If recipient bounces after delivery, delivered_count doesn't decrease
  - If recipient unsubscribes, no separate count (status='UNSUBSCRIBED')

Rates (computed in frontend):
  - Delivery Rate = (deliveredCount / totalRecipients) * 100
  - Open Rate = (openedCount / deliveredCount) * 100
  - Click Rate = (clickedCount / deliveredCount) * 100
  - Bounce Rate = (bouncedCount / totalRecipients) * 100

ERROR HANDLING
═══════════════════════════════════════════════════════════════════════════════

Handled Errors:
  ✓ Invalid payload (missing event, email, timestamp)
    → Response: 200 OK (log warning, don't crash)
  
  ✓ Duplicate webhook events (same providerEventId)
    → Response: 200 OK (ignore silently)
  
  ✓ Campaign not found
    → Response: 200 OK (log warning)
  
  ✓ Recipient not found
    → Response: 200 OK (log warning)
  
  ✓ Unexpected event type
    → Response: 200 OK (log as unknown)
  
  ✓ Malformed metadata
    → Response: 200 OK (log error)
  
  ✓ Database errors
    → Response: 200 OK (log error)

Strategy:
  - All webhook errors return 200 OK to Brevo
  - Never retry failed events (Brevo will timeout)
  - Log all errors for investigation
  - Webhook failures don't block campaign sending
  - Frontend can show "Analytics loading" state while processing
