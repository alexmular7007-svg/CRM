═══════════════════════════════════════════════════════════════════════════════
CURRENT REACT QUERY STRUCTURE
════════════════════════════════════════════════════════════════════════════════

EmailCampaigns.jsx:
  const campaign = useQuery({
    queryKey: ['email-campaign', workspaceId, id],
    queryFn: () => emailCampaignService.getCampaign(workspaceId, id),
    enabled: !!workspaceId && !!id
  })
  
  const recipients = useQuery({
    queryKey: ['email-campaign-recipients', workspaceId, id],
    queryFn: () => emailCampaignService.listRecipients(workspaceId, id),
    enabled: !!workspaceId && !!id
  })

Pattern:
  ✓ Enabled flag for conditional fetching
  ✓ Query depends on workspace/campaign context
  ✓ Separate queries for different data
  ✓ Manual invalidation after mutations
  ✓ Loading/error/success states in UI

Implementation for Analytics:
  • Add new query: useQuery({ queryKey: ['email-campaign-analytics', ...] })
  • Depends on: ['email-campaign', workspaceId, id] for consistency
  • Can be triggered on-demand or auto-fetch with campaign data
  • Auto-refetch when campaign sent (invalidate key)
