WHAT IT FIXES
═══════════════════════════════════════════════════════════════════════════════════

BEFORE FIX:
  User deletes workspace
  ↓
  FK constraint violation: "Key still referenced from attachments"
  ↓
  500 error, workspace not deleted
  ↓
  User blocked, cannot delete workspace

AFTER FIX:
  User deletes workspace
  ↓
  Attachments deleted → cache cleared
  ChatMessages deleted → cache cleared
  ... (all phases with cache cleared)
  ↓
  Workspace deleted successfully
  ↓
  User sees success message ✅

═══════════════════════════════════════════════════════════════════════════════════
WHY IT WORKS
═══════════════════════════════════════════════════════════════════════════════════

The Problem:
  Hibernate keeps deleted Attachment records in L1 cache (stale refs)
  PostgreSQL FK check sees cache: "Attachments still exist!"
  Deletion blocked → 500 error

The Solution:
  clearAutomatically = true clears cache after each DELETE
  Next operation sees actual DB state: "Attachments gone!"
  Deletion proceeds → Success ✅
