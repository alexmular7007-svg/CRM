KEY IMPLEMENTATION DECISIONS
═══════════════════════════════════════════════════════════════════════════════

DECISION #1: Rate Limiting Implementation
  Chosen: Custom @RateLimit annotation + RateLimitInterceptor
  Rejected: Spring Cloud Resilience4j
  Rationale:
    - Minimal scope: no new external dependencies
    - Token bucket algorithm: industry-proven, efficient
    - Easy to understand and maintain
    - Per-IP tracking via ConcurrentHashMap (simple, no database)
    - Full control over configuration

DECISION #2: Workspace Isolation
  Chosen: AOP aspect (@WorkspaceScoped) with method-level validation
  Rejected: Manual checks in every controller method
  Rationale:
    - Cross-cutting concern: best handled by AOP
    - Annotation-driven: declarative and clean
    - Single place to maintain logic (aspect)
    - Reusable across all controllers
    - Preserves existing method signatures (no API breaks)

DECISION #3: Async Transaction Management
  Chosen: Helper methods with @Transactional(propagation=REQUIRES_NEW)
  Rejected: @Transactional on entire @Async method
  Rationale:
    - @Async loses class-level @Transactional context
    - Each database operation needs own transaction
    - REQUIRES_NEW: creates new transaction regardless of existing one
    - Prevents data loss in async email processing
    - Minimal code change

DECISION #4: Metadata Validation
  Chosen: Comprehensive validation in extractLongFromMetadata()
  Rejected: Lenient parsing (accepts 0 or negative IDs)
  Rationale:
    - Prevent silent failures downstream
    - Catch malformed metadata early
    - Log all validation issues for debugging
    - Positive ID validation: IDs must be > 0
    - Type safety: Number or String only

DECISION #5: Security Headers
  Chosen: HSTS, X-Content-Type-Options, X-Frame-Options in SecurityConfig
  Rejected: Hiding behind reverse proxy only
  Rationale:
    - Defense in depth: application + proxy level
    - Spring Security provides easy configuration
    - Documented in code for maintainability
    - HSTS preload: protects against initial HTTPS downgrade
    - No performance impact
