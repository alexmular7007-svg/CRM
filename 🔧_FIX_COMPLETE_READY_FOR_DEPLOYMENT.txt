WHAT WAS FIXED
═══════════════════════════════════════════════════════════════════════════════════

PROBLEM:
  Workspace deletion failed with FK constraint violation:
  "update or delete on table 'chat_messages' violates foreign key constraint
   on table 'attachments'. Key(id)=168 is still referenced."

ROOT CAUSE:
  Hibernate persistence context was caching deleted Attachment entities
  causing PostgreSQL FK validation to fail (it saw cached state, not actual DB)

SOLUTION:
  Added @Modifying(clearAutomatically = true) to 18 repository delete methods
  This clears the L1 cache after each bulk delete, forcing next operation
  to see the actual database state instead of cached entity references
